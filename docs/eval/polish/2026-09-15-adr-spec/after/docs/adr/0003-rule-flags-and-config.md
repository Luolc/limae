# ADR-0003：规则 flag 化的配置模型 (`disable` 键、两种同构载体、CLI 优先)

- 日期：2026-08-31
- 承接：ADR-0002 的前两条 (逐条规则开关、配置经 toml)；该 ADR 的第三条 (Rust 主实现) 不在本次范围

## 背景

ADR-0002 只定了方向，把 flag 命名和配置文件的发现顺序留到日后另起 ADR。现在需要落地：各消费仓库的写作偏好不同 (例如有的仓不想要 R3 的括号外侧空格)，因此需要能逐条关闭规则。

约束有两条。**一是不能改变默认行为**：本仓已经被消费方按 tag 固定消费，升级到带配置的版本但不添加任何配置时，报告与 `--fix` 的结果必须与 v0.1.1 逐字相同。**二是规则集要能扩展**：英文规则集在计划中，配置键不能只适用于中文规则。

配置模型以 `spec/rules.md`「配置」为准 (normative)，与语言无关，各实现都按此实现；本文件只记录决定与理由。

## 决定

### 一、只能关，不能开

配置唯一的作用是从「全部规则」中减去几条，没有 `select` / `enable` 这类反向键。默认全开，「没有配置」永远等价于「全开」 —— 这直接满足了上面的第一条约束，也确保各实现的默认行为不会分叉。

未采纳的替代方案：仿 ruff 的 `select` + `ignore` 双键。双键需要定义二者如何相互作用 (谁先谁后、能不能同时给)，而现在只有三条规则，也没有人要求「只开某几条」 —— YAGNI；真正需要时再加 `select` 是向后兼容的扩展。

### 二、一个键 `disable`，元素是规则 id

`disable = ["R3"]`。按稳定 id 组织的好处是，规则集扩张时不需要新增键：英文规则将来有自己的 id，直接写进同一个列表；不设「中文 / 英文」这类分组，也不为每条规则设置一个子表 (那会为「开关」这一件事多出一层嵌套)。

未知 id 是配置错误，实现必须报错退出 (Python 参考实现用退出码 2)，不得静默忽略 —— 拼错 id 或规则改名会立刻暴露，而静默忽略会让人以为规则已经关闭。

### 三、两种同构载体：`lo-md-lint.toml` 与 `[tool.lo-md-lint]`

独立文件 `lo-md-lint.toml` 将键写在顶层，`pyproject.toml` 将同样的键写在 `[tool.lo-md-lint]` 表中，键结构完全一致，只是外层位置不同。Python 生态的消费方本来就有 `pyproject.toml`，不必为三行配置新增一个文件；不是 Python 项目的消费方 (machine-setup 这类) 则使用独立文件。同构意味着配置可以直接在两者之间剪切粘贴，文档与实现也只有一份键定义。

独立文件只认 `lo-md-lint.toml` 这一个名字，不支持 `.lo-md-lint.toml` 这类隐藏文件变体：多一个名字就多一条决定优先级的规则。

### 四、发现：从 cwd 向上到仓库根，最近的一层整份生效

从当前目录逐级向上查找，同一目录中 `lo-md-lint.toml` 优先于 `pyproject.toml` 中的表，含 `.git` 的目录是最后一层。找到一份后，就完整采用这份配置，**不与更上层的配置逐键合并** —— 合并需要定义列表是并集还是覆盖，调试时也难以说明最终配置的来源；「最近者全赢」一句话就能说清。

发现过程中读到的候选文件必须是合法 toml，解析失败即为配置错误，当场退出，不跳过，也不继续向上查找 —— 包括 `pyproject.toml` 不含 `[tool.lo-md-lint]` 表的情况。理由是解析失败时无法判断其中是否有本工具的表，「跳过坏文件继续找」会把「用户的配置写错了」静默变成「按默认全开跑」，而坏掉的 `pyproject.toml` 本来就该修。这条对所有实现都是规范的一部分 (`spec/rules.md`「配置错误」)，不留给各实现自行选择，否则同一个仓库在 Python 版与 Rust 版下的行为会分叉。

发现只看当前工作目录，不看被检文件的路径：一次运行只使用一套配置。按文件路径分别取配置 (每个文件走自己的目录链) 才是 monorepo 中的完整答案，但这要求实现按目录分组、缓存配置，而现在的消费方都是「在仓库根跑一次」 —— 同样是 YAGNI，需要时再扩展，且扩展方向与本模型不冲突。

### 五、CLI `--disable` 优先，且整体覆盖配置文件

`--disable R1,R3`、`--disable R1 --disable R3` 等价；命令行上只要出现 `--disable`，配置文件整体就不生效。整体覆盖而不是叠加，是为了让「临时试一把不带某条规则的效果」有确定结果，不必先读取仓库中的配置文件。`--fix` 与 `--all` 的语义不变。

## 后果

- 版本升到 0.2.0。不加配置的消费方升级是 no-op：默认启用集就是全部规则，`check` 与 `fix` 的代码路径在全开时与 v0.1.1 逐字等价，`spec/fixtures/` 中原有的黄金 case 一条未改，仍全部通过。
- 黄金集新增一个配置维度：case 可以带一个可选的第四个文件 `<case>.conf`，内容就是独立配置文件的内容 (`spec/README.md`)。新增的三个 case 覆盖「关 R1」「关 R3」「显式全开」。
- 将来的英文规则集不需要修改配置模型，只需在 `disable` 中增加几个可写的 id。
- Rust 实现按 `spec/rules.md`「配置」实现同一套语义，包括发现顺序与未知 id 报错。

## 状态

accepted (2026-08-31)。
