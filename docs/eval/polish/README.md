# polish 的前后样本 (eval set)

这里冻结 `limae polish` 每一次在本仓文档上实跑的**前后两份原文**，供以后迭代 prompt 与词典时做对比。它不是文档，是材料。

## 为什么要留

改 prompt 之后想知道「这次比上次好还是坏」，只有一条路：拿同一份输入，比两次输出。输入不留下来，这个比较就做不成 —— 而 git 历史里虽然有 `before`，但被丢弃的、没合入的那些输出不在历史里，那恰恰是迭代时最想看的一批。

## 目录

一次运行一个目录，命名 `<日期>-<批次>`：

- `before.md` —— 改写前，逐字，出处是 `run.md` 里记的那个 commit。
- `after.md` —— 改写后，走完 `polish` 与 `--fix` 两步之后的文件。
- `run.md` —— 这一轮是怎么跑出来的：基线 commit、命令、引擎、prompt 与词典各自最后一次改动的 commit、改动量；末尾留给裁决。

## 判据从哪来

**裁决人是用户，用户的反馈就是 golden standard。** 这里不定义任何自动判据 —— 本仓自己的 linter 量的是列出来的词与排版，量不了「这次改写好不好」，拿它当判据是零分辨力。将来要不要造 metric，等样本攒够、用户给过几轮裁决之后再说，那时判据也要拿用户已经给过的裁决去校准。

裁决记在各自的 `run.md` 末尾，写日期，**照抄用户的原话，不要改写** —— 改写过的裁决就不是 golden standard 了。

## 这些文件不进 linter

`before.md` 是被冻结的历史原文，`after.md` 是被冻结的模型产物，两份都不许被 `--fix` 动。仓根的 `.limae-ignore` 因此排掉整个 `docs/eval/`。这也意味着**扫全仓的计数 (如某个词出现多少处) 会把这里的样本算进去**，量的时候要自己排除。
