# ADR-0013：移除更名过渡期的全部旧名别名

- 日期：2026-09-03
- 承接：ADR-0008 §一 (更名对账表：仓名 / 包名 / 命令名 / hook id / 配置表与文件 / 指令前缀 / 忽略文件) —— 本 ADR 关掉那张表里的过渡期；ADR-0003 §三 (两种同构配置载体) 的键结构不变，只是不再认旧拼法

## 背景

本工具原名 `lo-md-lint`，ADR-0008 定下改名为 `limae`，并按「新旧并存、消费方自行迁移」的方式落地：命令名、pre-commit hook id、配置文件名与表名、行内指令前缀、忽略文件名六个面，每一面都同时认新名与旧名，语义完全相同。这是过渡期该有的样子 —— 改名不该在消费方毫无准备时把它们的 CI 打红。

过渡期的前置条件今天已经解除。用户 2026-09-02 用 `gh repo list Luolc` 加全仓 `gh search code` 核过覆盖面：三个消费仓 (butler、wealth-management、machine-setup) 全部改用新的 `repo` / hook id / 命令名，**旧配置语法在全部仓零命中** —— 旧指令前缀、`[tool.lo-md-lint]` 表名、`lo-md-lint.toml`、`.lo-md-lint-ignore` 一处都没有。所以这次移除对已知消费方是 no-op，不需要任何跨仓协调。

留着不删是有成本的，而且成本落在最不该有分支的地方：配置发现顺序里为「同一层新旧同名并存」专门开了一条配置错误 (规范第 10 条)，忽略文件那边又为同一种并存开了相反的一条 (新名优先、不报错)，两条规则各自成立、合在一起却要用一整段解释判据为什么不矛盾。这段解释的存在理由就是旧名本身。规范里每多一条这样的条目，后续的 Rust 实现就多一处必须复刻的行为。

用户 2026-09-03 裁定：清干净，六个面一次性全删。

## 决定

### 一、删掉的面

- **命令名**：`pyproject.toml` 的 `[project.scripts]` 只留 `limae`，删掉 `lo-md-lint` 入口。
- **pre-commit hook id**：`.pre-commit-hooks.yaml` 只留 `- id: limae`，删掉别名 hook。
- **配置文件名**：只认 `limae.toml`，不再认 `lo-md-lint.toml`。
- **配置表名**：只认 `[tool.limae]`，不再认 `[tool.lo-md-lint]`。
- **行内指令前缀**：只认 `limae-disable` / `limae-enable` / `limae-disable-next-line`，不再认 `lo-md-lint-` 一族。
- **忽略文件名**：只认 `.limae-ignore`，不再认 `.lo-md-lint-ignore`。

规范 (`spec/rules.md`) 里描述旧名的段落一并删除，包括「同一层新旧同名并存是配置错误」这条配置错误 (原第 10 条) 与忽略文件那条相反的「新名优先」。两条都是为新旧并存而生，旧名没了它们就没有可能触发的输入。黄金 fixture `legacy-directive-prefix` 整组删除；`spec/fixtures/` 里描述新前缀行为的 `inline-disable-*` 三组不变，新前缀的覆盖不依赖被删的那组。

### 二、不补替代 fixture

被删的 `legacy-directive-prefix` 除了「旧前缀被识别」之外还带了一个 case：`<!-- lo-md-lint-disabled -->` 这种拼错的名字是普通文本。这一点由规范里通用的那条覆盖 —— 「名字拼错的注释 (如 `limae-disabled`) 按普通文本处理」 —— 而新前缀的同款 case 已经在既有 fixture 里。**不为「旧前缀不再生效」补负向 fixture 或负向测试**：旧前缀今天与任何其它拼错的名字没有区别，为它单独立一个断言，等于在规则集里长期供养一个已经不存在的概念。

## 后果

- **0.13.0 起旧名一律失效。** 移除别名是 breaking change，版本从 0.12.0 跳到 0.13.0。消费方若还有旧写法，hook id 与命令名这两面会硬失败 —— pre-commit 找不到 hook id，shell 找不到命令。仓库地址不在此列：仓名改在本次移除之前就已完成 (ADR-0008 §一)，旧 URL 由 GitHub 301 永久重定向，`repo:` 与 `uvx --from git+…` 写旧地址照旧能用。
- **旧配置文件会被静默当成「没有配置」，不报错。** 这是这次移除里唯一不响的行为变化，也是最值得写下来的一条：发现顺序找的是 `limae.toml` 与 `[tool.limae]`，一份留在原地的 `lo-md-lint.toml` 既不是配置来源、也不是配置错误 (规范里「没读到就不算错」)，于是这次运行按默认全开跑。表现是「规则突然多了 / 关掉的规则又报了」，而不是一条错误信息。`.lo-md-lint-ignore` 同理：文件还在，但不再排除任何东西，被忽略的文件会重新进入检查。**已知的三个消费仓都没有这类残留文件，所以这条今天没有受害者。它针对的是任何一个还留着旧配置文件或旧忽略文件的 pre-0.13 消费方 —— 0.12 本身仍然识别旧拼法，所以受影响的不只是从更早版本跳上来的仓库。**
- **规范少了一条配置错误。** 配置错误清单从 10 条回到 9 条。编号是清单内的序号、不是稳定 id，实现不据此分流，删掉一条不影响其余各条的含义。
- **ADR-0008 §一 那张对账表里的「待做」不再更新。** 按守则，ADR 被新 ADR 取代而不就地改写 —— 那张表记录的是它写下时的状态，本 ADR 是它的后续。

## 状态

accepted (2026-09-03)。
