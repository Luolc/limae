# ADR-0017：`limae polish` 文件模式 —— 每次调用显式授权、引擎起在导出视图里、limae 是唯一写入者

- 日期：2026-09-13
- 承接：ADR-0008 §二 (三个子命令)、§六 (失败语义)、§七 (产物原地改)；ADR-0016 §七 (polish 是 CLI 里的功能，与 skill 并列)。
- 证据：两位独立裁决方的两轮 debate 报告，原样归档在 [`docs/research/polish-file-mode-debate-astra.md`](../research/polish-file-mode-debate-astra.md) 与 [`docs/research/polish-file-mode-debate-fable.md`](../research/polish-file-mode-debate-fable.md)；本仓实现时的引擎实测在 [引擎行为实测](../research/polish-engine-cli-behavior.md) §七。

## 背景

`limae polish -` 至今只有 stdin 模式：一段文本进、改写出，引擎起在一个空的临时目录里、拿一份白名单环境 (ADR-0008 §三)。用户要的下一步是 `limae polish <files>` 与 `limae polish --all`：把仓库里的文件原地改写，并让引擎能读仓库里的其它文件做参考 (术语、名字、交叉引用)。

这一步改变了两件事，两件都是隐私与完整性边界：引擎会**读到仓库**，读到的会**发给引擎的服务方**；而「原地改写」意味着有东西要**写用户的仓库**。用户 2026-09-12 为此开了一场两轮 debate (两位最高档 agent 独立裁决、第二轮互读)，四个问题：授权放在哪一层 (Q1)、「只改这几个文件」能承诺到什么程度 (Q2)、机密性与完整性要不要分成两个开关 (Q3)、prompt injection 是真风险还是剧场 (Q4)。用户按两份报告裁定了下面的设计；本 ADR 记决定与被否掉的方案，不重新论证。

两份报告**唯一完全一致的结论**先放在最前面，因为它决定了文档怎么写：**机密性这条路上没有真正的技术缓解，只能 opt-in 加告知。** 引擎读到什么就把什么发给服务方，这是文件模式的定义本身；能做的是让用户每次都知情地选择，并把「读到的东西去了哪里」写在用户看得见的地方 (§五)。

## 决定

### 一、授权 = 每次调用的显式 flag，不做用户层信任记录

`limae polish <files>` 与 `limae polish --all` 必须带 `--share-repo-with-engine`；没有它而给了文件参数或 `--all`，**在任何引擎探活或启动之前**以退出码 2 拒绝，错误文本解释这个模式会做什么。配置文件与环境变量**不能**授予它；单靠 positional (文件参数、`--all`) 不够；不叠加第二道开关。`-` 与这个 flag 同时出现是参数冲突：stdin 模式一行不变，永远不需要授权。

flag 的名字要说清它授予了什么，不只说「read」：授予的是「把仓库的一份副本交给引擎，引擎读到的会发给它的服务方」。

**为什么是 flag 而不是信任记录**：Fable 第一轮推荐 git `safe.directory` 那样的用户层信任记录，Astra 第一轮推荐每次 flag，第二轮两人**互换了立场**又各自收窄，最后收敛到 flag。决定性的论证是 Astra 那句：能让你跑它 Makefile 的仓库，本来就能在 Makefile 里直接写 `claude -p …`，limae 的任何授权层在那个场景里都不是边界。于是两个候选在「仓库代码已获执行」的场景下失败得一样，在「用户自己敲命令」的场景下都是显式的；差别只剩状态放在哪 —— 信任记录是一份持久的、按路径的、跨机器不一致的隐藏状态，附带「过期、一次性还是持久、怎么撤销」三个没人能答的问题；flag 没有任何隐藏状态。按「不 over-engineering」与「没想清楚时失败得最安全」两条判据，flag 都赢。

**flag 挡不住什么，必须明写**：它会被写进 Makefile、justfile、`.pre-commit-config.yaml` 的 `args`、CI step，而这些文件都在仓库里 —— 之后的调用者只看到 `make polish`。这是我们知情选择的代价；写清楚比假装解决了强。它进 `--help` 与 README，不只埋在这里。

### 二、引擎起在一份导出视图里，不是用户的真仓库

文件模式把仓库的 **tracked 文件** (`git ls-files` 列出的) 拷进一个一次性的私有目录，引擎在那里启动。视图里**没有 `.git`、没有被忽略与未跟踪的文件、没有 `.claude` / `.codex` / `.grok` 目录、没有 `.mcp.json`**；符号链接、submodule、已从工作树删除的 tracked 路径都不复制。每次 `limae polish` 调用建一份视图，同一次调用的每个目标文件各起一次引擎；视图是拷贝，同一次调用里先写回的目标在视图里是旧版本。

理由是**结构性的**：恶意配置根本不在引擎启动的目录里，所以没有任何引擎会加载它。这比靠三家各自的「关掉项目配置」flag 稳，因为 flag 会随版本过期，而「这个目录里没有那个文件」不会。**但要把这句话的两半分开看**：「引擎起在一份拷贝里、不在真仓库里」这一半是正向的；「拷贝里没有哪些东西」这一半今天是一张名字清单 (`rust/polish/view.rs` 的 `EXCLUDED_NAMES`)，清单只能覆盖已经想到的名字 —— 定稿时是三个点目录，实现时实测多出 `.mcp.json`，第五个是什么今天没人知道，而它在视图里与已堵住的四个长得一样。orchestra 在实现 PR 里提出的正向候选是**视图只放 `*.md`**：polish 的目标只可能是 Markdown，「读别的文件做参考」是锦上添花，只放 Markdown 则配置文件是因为类型而不在、不是因为名字而不在，且不随任何引擎版本变。这条记进 `docs/tracker.md`，触发点是下次发现第五个需要排除的名字时。实测证明了要挡的东西是真的 (§七 A1–A5)：仓库自带的 `.claude/settings.json` 里的 `SessionStart` hook 在 `claude -p` 下**模型没开口就执行了**；把同一个仓库经文件模式跑一遍，探针文件不出现；只拿掉导出视图 (在真仓库里起) 就出现；再跑一遍又出现。`.mcp.json` 是实现时补上的 (§七 A6、A9)：一份只含 `.mcp.json` 与正文的视图在默认 flag 下照样起了那个 MCP server 的进程，所以它也不能进视图 —— 判据是「引擎会不会因为这个文件的存在而运行什么」，不是「它在不在点目录里」。

**视图挡住的是执行，不是指令**。仓库自带的 `AGENTS.md` / `CLAUDE.md` / `GROK.md` 是 tracked 的散文，**在视图里**；debate 的 Fable 侧实测三家在仓库目录里都会加载并照做这类项目文档 (3/3 对 0/3)。视图对它们只做到一件事：它们不会因为在场而**运行**什么。它们会不会进模型上下文由纵深那一层决定，而那一层三家不一样：codex 的 `-c project_doc_max_bytes=0` 正是关这个的 (Fable F3)；claude 的 `--setting-sources user` 实测让上下文里只剩家目录那份 `CLAUDE.md`、项目那份不再列出 (Fable 第二轮 C3，n=1)；grok 在未 `--trust` 的目录里不在启动时加载项目文档 (Fable G1)，而视图每次是一个新路径、永远不在信任表里。三条都是 flag 与 n=1 的读数，不是结构；且三家的文件工具都读得到视图里的这几个文件，读了会不会照做是模型当场的决定 (本仓实测 A8 三家输出都没有 fixture 里 `CLAUDE.md` 要求的标记，同样 n=1)。**这是知情的取舍，不是待办**：不把它们排除，因为一个仓库的 `AGENTS.md` 往往写着这个仓自己的行文约定，让润色模型读到是有益的；代价是仓库能对模型**说话**、只是不能让它**运行**东西，§五 的措辞要把这句写给用户。

**排除不等于隔离**：视图减少的是自动发现，不是能力。引擎带着文件工具，按绝对路径交给它的、或它猜到的视图之外的文件，它仍然读得到 —— grok 在文件模式的只读工具集下读到了视图外的合成文件 (§七 A7)；claude 在 `-p` 下把文件工具限制在工作目录、读不到，codex 回答读不到但没有证据说明是沙箱还是模型 —— 三家不一致，所以文档按最弱的一家写。`HOME` 下的东西 (各家配置、登录态、全局守则) 照样自动加载，与 stdin 模式相同 ([引擎行为实测](../research/polish-engine-cli-behavior.md) §一)。

### 三、引擎侧的只读工具集与关配置加载照加，作为纵深

视图之上，每个预设在文件模式下多带一组 flag：claude `--setting-sources user --no-session-persistence --tools Read,Glob,Grep`；codex `--sandbox read-only -c project_doc_max_bytes=0`；grok `--tools read_file,list_dir,grep --disable-web-search`，永远不带 `--trust`。这些是两份报告里各家实测过有效的 (grok 的 `--disallowed-tools` 实测无效，所以用允许名单)。它们是纵深，**不是承重的那一层**：flag 随 CLI 版本变，视图不变。**`custom` 引擎在文件模式下直接拒绝** (退出码 2，不论它来自 `--engine`、`LIMAE_ENGINE` 还是配置文件；判据是回归臂里那条命令从未启动)：它的命令来自仓库自己的 `limae.toml` —— 本仓没有用户层配置 (`find_config` 只沿祖先目录走到 `.git` 为止)，文件模式下 `command` 的**唯一**来源就是被检查的仓库；它又继承调用者完整环境 (白名单只对预设生效)，limae 没有任何手段约束它运行什么、写到哪里。接受它等于让仓库自己选要跑的程序，正是视图要挡的那件事。第一版把它写成「只换工作目录」，审查方以 P0 抓出 (仓库配置一条写视图外标记的 custom 命令，文件模式退出 0、绊线看不见)。「只在显式 `--engine custom` 时允许」也不成立：flag 只表达「用 custom」，argv 仍 100% 由仓库提供，一个只为了告诉用户别用它而存在的开关不是边界 (§六)；没有用户侧配置层这一条，让这句从论证变成机制 —— 不是不愿给用户一条安全的 custom 路径，是文件模式下那条路径今天不存在。**作用域**：本 ADR 里「引擎起在导出视图里」「仓库不能让引擎运行任何东西」这类承诺**只对文件模式**为真；stdin 模式的 `custom` 不变，仍是用户自己的命令、保留调用方的目录与环境，边界由用户自己划 (ADR-0008 §三，[引擎行为实测](../research/polish-engine-cli-behavior.md) §一末段)，同一条「仓库配置能选命令」的路径在那里今天就有，记在 `docs/tracker.md`、触发点是下一次动 stdin 模式的引擎解析时。

prompt 多一层 `spec/polish/file-mode.md`：告诉模型正文来自仓库里的哪个文件、它被起在一份 tracked 文件的副本里、可以读其它文件做参考、什么都不要写 —— 改写是**返回**的，不是写的。

### 四、limae 是唯一的写入者，哈希对比降级为绊线

引擎只回正文，走与 stdin 模式相同的答案通道；limae 写目标文件，且只写命令行上点名 (或 `--all` 选出) 的那些。「limae 的写回只改这几个文件」由构造保证 —— limae 里写文件的代码只有这一处。**这句的作用域是 limae 自己的写回路径，不是「本次调用除 limae 外没有东西写盘」**：引擎进程本身、以及用户家目录里的引擎配置仍可能在视图之外写盘 —— 审查方实测 `~/.claude/settings.json` 里的 `SessionStart` hook 在文件模式的 `--setting-sources user` 下照跑、往仓外写了标记，换成 `--setting-sources project` 的对照臂不写；这是 `HOME` 放行的既定取舍 ([引擎行为实测](../research/polish-engine-cli-behavior.md) §一第 2 类)，用户自己在家目录里配的东西 (hook、MCP server) 对用户自己的机器做事，与 stdin 模式下用户自己的 `custom` 命令是同一类 (ADR-0008 §三：边界由用户自己划)，而上一段拒绝仓库来源的 custom 正因为它**不是用户选的** —— 两件事用同一把尺子量：limae 挡的是「仓库能选」，不是「这台机器上没东西会跑」；不去关用户层 hook，那是逐家 flag 的纵深层，拿它兜一句字面保证等于把承重挪到最松的一层。绊线只看视图，看不见它们。这句保证的主语是仓库，不是这台机器；用户文档按这个作用域写。

**写回前核对目标仍是跑前那一版**：每个目标在起引擎之前读一次原始字节，写回之前再读一次，不同就拒绝写、保留外部编辑 (编辑器、formatter、并发的另一次 polish)，报 `not written` 并以退出码 1 收尾；**不得用 HEAD 覆盖** —— 那会抹掉用户启动前未提交的内容。这条是 Astra 的方案里被采纳的那一半 (「导入前核对目标是否仍是运行前版本，冲突则拒绝覆盖」)。目标是符号链接时：命令行点名的拒绝 (退出码 2，请点名它的目标)，`--all` 选出来的跳过并说明 —— 它的目标在同一次 walk 里、以自己的名字被 polish。硬链接分不出来、照 `--fix` 的做法写穿，列为已知不管。

**绊线 (tripwire)**：视图在引擎跑之前拍一次快照 (每个路径的长度与内容哈希)，每次引擎调用之后再拍一次比对；有差异 (新增、删除、改动) 就报 `tripwire`、**这一轮的答案不写**、整个运行停下、退出码 1。它防的是预设的只读 flag 失效 —— 某次 CLI 升级改了默认沙箱、`--tools` 语义变了、工具名被上游改名而允许名单静默变空 (grok 对未知名字不报错)。它是事后检测、不是写入隔离，且只看视图：仓库、家目录、网络它都看不见。**不写成事务、不自动全仓回滚**：两份报告一致否决了「哈希 + 回滚 = 只许改指定文件」 —— 内容哈希对 mode 位、`.git` 内部、被忽略文件、写后恢复、硬链接换目标全部零分辨力，且「agent 越界」与「用户自己编辑」给出同样的差异，无归属的全仓回滚会吃掉用户的编辑。

### 五、承诺的措辞

文档 (README 的 polish 一节、flag 的 `--help`、拒绝时的错误文本) **不许写「只会改你指定的文件」**。下面每一条的作用域都是**文件模式**，不是全局 —— `limae polish -` 的边界由 ADR-0008 §三 写。要写的是：

- 这个模式会让本机 coding agent 读到导出视图里的内容，并把它读到的发给该引擎的服务方。
- 导出视图排除了什么 (`.git`、被忽略与未跟踪的文件、`.claude` / `.codex` / `.grok`、`.mcp.json`)，**以及排除不等于隔离** —— 引擎按绝对路径仍读得到视图之外的文件。
- 视图挡住的是执行、不是指令：仓库的 `AGENTS.md` / `CLAUDE.md` / `GROK.md` 在视图里，引擎读得到，读了会不会照做由模型当场决定。
- 写入侧是事后检测加冲突拒绝，不是写入隔离。
- flag 挡不住它被固化进 Makefile / justfile / `.pre-commit-config.yaml` 的 `args` / CI step —— 这些文件都在仓库里。

### 六、被否掉的方案

- **完整副本 + 外部强制隔离 (Astra 第一轮)**：在一份外部强制只读的仓库副本里跑全工具的 agent，limae 只导入指定文件的结果。否掉的理由是它要求一个本机不存在、limae 不该自己造的 OS 沙箱 (grok 的 `--sandbox` 四个 profile 全因 `bwrap` 缺席报错；codex 的沙箱是它自己的、罩不了别家) —— 没有 OS 边界时，副本只是副本，一个带 shell 的引擎 `cd` 回原路径一步就够；这是一个比 polish 本身大的工程，与「不 over-engineering」正面冲突。副本的另一半 (「引擎读到的集合由 limae 定义」) 被保留为 §二 的导出视图。
- **用户层信任记录 (Fable 第一轮)**：见 §一。Fable 第二轮自己撤回。
- **仓库配置键 / 环境变量授权**：两份报告一致否决 —— 那是把「同意」放在攻击者能写的位置。
- **两个开关 (读一个、写一个)**：两份报告一致否决 —— §四 之下引擎没有写能力，「引擎会改你的文件」不再是用户要承担的风险；一个存在只是为了劝人别开的开关是陷阱，且会制造「我只开了读」的错误安全感。
- **哈希 + 自动回滚当作事务**：见 §四。
- **靠那条「输入是材料不是指令」的 prompt 规则缓解注入**：两份报告一致 —— 它是对待改写正文的质量指令，不是权限边界；有一层根本没有模型参与 (§二 的 hook)。保留规则，不把它算进任何保证。

## 后果

- 用户得到 `limae polish --share-repo-with-engine <files>` 与 `… --all`，输出每个目标一行 (`polished:` / `unchanged:`)，诊断进 stderr；`limae polish -` 一行不变。
- `--all` 的目标选择与 `limae --all` 完全相同 (走同一个 walker 加 `.limae-ignore`)，所以 `.gitignore` 与 `.limae-ignore` 都被尊重；**但这两份 ignore 只决定改写哪些文件，不决定引擎读到哪些**：视图是 `git ls-files`，被 `.limae-ignore` 排除的 tracked 文件仍在视图里，引擎读得到；被 `.gitignore` 排除的不在。文档要把这两半分开写。
- 跨文件的协调改写 (ADR-0008 §十 P2) 在这个设计下做不了：引擎没有写能力。到 P2 时再开一个**每次调用的**显式 flag 让引擎拿写权限，并把 §五 的措辞一起改。
- ADR-0008 §八 的结构核对 (改写前后围栏、行内代码、链接、标题逐字不变) 在 Rust 里尚未实现 (`docs/tracker.md` 备查项)，文件模式的写回没有它，靠人看 diff；与 stdin 模式相同，不是本次引入的缺口。
- 每次引擎调用之后重新哈希整个视图，代价与 tracked 文件总量成正比；对散文仓库可忽略，对带大体积 tracked 资产的仓库会明显。先接受，等真实读数再议。
