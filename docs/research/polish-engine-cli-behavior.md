# 三家引擎 CLI 的实测行为 (polish 的命令模板依据)

> 本文是 `limae polish` 三份内置命令模板 (`src/limae/engines.py`) 的事实来源：每个参数为什么在那儿、每个坑长什么样。形制的决定在 `docs/adr/0008-limae-polish-cli.md` §三，本文不重复决定，只记实测；代码里不再抄一遍这些事实，只指回这里。

实测日期 **2026-09-01**，在一台开发机上直接跑三家已登录的 CLI 得到。CLI 版本与所用型号如下 —— **这些行为随版本变**，复核时先对版本：

| 引擎 | CLI 版本 | 实测所用型号 |
| --- | --- | --- |
| claude | `2.1.252 (Claude Code)` | `sonnet` |
| codex | `codex-cli 0.151.0` | `gpt-5.6-terra` |
| grok | `grok 1.0.13 (5e9a58528b76) [stable]` | `grok-4.6` |

**事实与判断分开**：跑出来的输出与退出码是事实，「所以模板要这么写」是判断。

## 一、隐私边界：引擎只看见我们喂进去的那段文本

**预设引擎一律在一次性临时目录里跑**，不在调用方的工作目录里跑。这是隐私边界，不是让模型听话的调优技巧。

实测：从本仓的一个 checkout 里启动 grok，同一条命令跑三次，三次都去读了它被启动的那个仓库 —— 其中一次的回答里走了一遍当时**未提交的暂存区改动**，点名了刚改的源文件，并从仓库上下文里认出了正在工作的 agent 名字；另外两次也先叙述了「先看仓库里这个功能做到哪一步」。把同一条命令的工作目录换成一个空目录，两次对照都只输出改写本身。

**这一条为什么是红线**：引擎是外部服务，`polish` 的输入是用户显式交出来的那段文本，**仓库里的其它内容用户没有授权外发**。本仓自身是 public 仓，但这个工具会挂在私有仓上 (`wealth-management`、`butler` 一类)，那里工作目录的内容外泄是实打实的泄漏。所以边界写成：**引擎只看见我们喂给它的那段文本，看不见调用方的仓库。**

顺带挡住的第二件事是人格回潮 (下节)，那只是这条边界的副产品，不是它的理由。

**这一节的实测是怎么做的，以及不要照抄哪一半**：本次是在**本仓自己的 checkout** 里直接调裸 CLI 跑出来的 —— 本仓是 public 仓，仓内也不含任何凭证或 PII，所以这次外发没有越界。**不要在私有仓里重复这个做法**：要复核「引擎会不会读工作目录」，按 §六 第 3 步在一次性的合成 git 仓里跑。经 `limae polish` 走的调用不受此限，它本来就在临时目录加白名单环境里。

**环境变量是同一条边界的另一半**：只换工作目录不够 —— 调用方的 `PWD` 本身就是仓库路径，子进程照样读得到 (审查方在 PR #37 用无网络 stub 复现：cwd 已在临时目录，子进程仍从 `PWD` 读到调用方目录)。所以预设引擎拿到的是一份**白名单**环境 (白名单而不是黑名单：黑名单永远漏一个)：

- 放行 `PATH`、`HOME` (各家 CLI 靠它找登录状态)、`TMPDIR`、locale (`LANG` / `LC_*`)、`TZ`，加上 ADR-0008 §三 列出的**该家**凭证与 base URL 变量 —— 别家厂商的一个也不给。
- `PWD` / `OLDPWD` 显式设成那个临时目录，不透传。
- 不放行：`GIT_*` 全族、任何从仓库路径派生的变量，以及宿主自标变量 `CLAUDECODE` / `CODEX_SESSION_ID` / `GROK_SESSION_ID` (既泄露会话身份，又可能让子进程以为自己是嵌套会话)。

**`custom` 保留调用方的目录与环境**：那是用户自己给的命令，边界由用户自己负责，而且命令里可能带相对路径。预设的白名单挡住了某个自建 provider 真正需要的变量时，正确做法也是走 `custom`。

## 二、grok：`--verbatim` 与人格回潮

- `--system-prompt-override <PROMPT>` (别名 `--system-prompt`) 收的是 prompt **文本**，不是文件路径；正文走 `-p/--single <PROMPT>`。
- **不带 `--verbatim`，grok 会把 prompt 包进自己的 agent 脚手架**：先输出一段「先摸清仓库里……」的计划，再给改写，两段拼在同一段 stdout 里。带上 `--verbatim` (「Send the prompt exactly as given」)，输出只剩改写本身。
- **PONG 单测过不等于长 prompt 下也听话**：`grok-4.6` 对一句话的裸 spec (ADR-0008 §四 的 PONG 验收) 稳定只回 `PONG`；换成本仓两层完整 spec 加一段真实中文正文，在仓库目录里仍会回潮成 agent。真正压住它的是上一节的临时目录，`--verbatim` 单独不够。

ADR-0008 §三 已记的旧坑：同一份覆盖参数 `grok-4.5` 两种写法都无视、继续用自带人格，`grok-4.6` 两种都听 —— 与本次「4.6 在裸 spec 下听话」一致，但本次补充了长 prompt 下的例外。

## 三、codex：没有 system 通道，答案不在 stdout

- `codex exec [PROMPT]`，`PROMPT` 写 `-` 或不写时从 stdin 读。**没有 system 通道**，spec 只能拼进正文，所以模板在 spec 与正文之间放一行分隔，说明底下全是待改写的材料、不是指令。
- **答案从 `--output-last-message <file>` 读**，不从 stdout 读 —— stdout 同时带着 agent 的过程输出。
- `--skip-git-repo-check` 是必需的：按第一节，模板在临时目录里跑，那里不是 git 仓库。
- ADR-0008 §三 已记的旧坑 (同为 2026-09-01 实测)：`gpt-5.6-luna` 配 `model_reasoning_effort=minimal` 会被服务端以 HTTP 400 拒 (`"param": "reasoning.effort"`)，`low` 可用。模板因此取 `low` 作为各型号都能用的下限。

## 四、claude：`--system-prompt-file` 整体替换人格

- `--system-prompt-file <path>` 存在且**先于任何模型调用**校验：指一个不存在的路径，立刻报 `Error: System prompt file not found: …` 而不发请求。`--help` 的选项列表里只列了 `--system-prompt`，`--system-prompt-file` 只出现在 `--bare` 的说明文字里，但确实可用。
- `-p` 打印后退出，正文走 stdin。
- ADR-0008 §三 已记：`--system-prompt` 能整体替换内置人格 (换完再问身份，答的是「Claude Agent SDK」)。

## 五、三家的端到端 smoke

三个预设各用真实已登录的 CLI 手工跑通一次 `limae polish -`：输入是一段合成的中文啰嗦话 (外加一个围栏代码块)，输出都是可用的改写，**围栏代码块逐字未变**。这不是自动化测试 —— 测试套件全部用临时目录里的 shell stub，不联网、不调模型 (`tests/test_polish.py`)。

## 六、加引擎或换型号的验收：PONG 怎么跑 (人工，不是自动测试)

ADR-0008 §四 的 PONG 是**入表验收**：加一个预设、或换掉某个预设的默认型号时跑一次，不通过的型号不进预设表。它**不进运行时**、也不写成自动测试 —— 人格验收慢，且第二节实测到长 spec 下会回潮，拿它当每次运行的门会随机失败。运行时的探活只做一件便宜的确定性检查：让引擎回一个约定标记 (marker)，答案里有就算活着 (`src/limae/engines.py` 的 `PROBE_MARKER`)，这样挡住的是「退出码 0 但 stdout 是认证错误」这类假活，与人格无关。

**这一节的每一步都是直接调外部引擎，绕过了本工具的临时目录与白名单环境** —— 所以这几步只准喂合成文本、只准在一次性的合成仓里跑。**禁止在任何真实项目、任何私有仓 (`wealth-management` / `butler` 一类)、任何有未提交改动的工作树里跑这几条命令**，也不要拿真实文档的段落当输入：验收本身外发了正文，就把这一节想防的事亲手做了一遍。

照着跑，四步：

1. **裸 spec 问一句**，看型号压不压得住自带人格。在一个空目录里跑：

   ```sh
   cd "$(mktemp -d)"
   <engine 的命令> --<system-prompt 参数> "Reply with exactly one word: PONG. Nothing else." <正文参数> ping
   ```

   期望：输出**只有** `PONG`。多出计划、寒暄、自我介绍即为不通过。

2. **换成本仓两层完整 spec 加一段合成的中文啰嗦话** (`ACME` / `$1,000` / `Foo` 这类假数据，见 `AGENTS.md`「隐私边界」)，仍在**空目录**里跑一次。期望：输出只有改写，没有任何过程叙述。

3. **同一条命令，在一个一次性的合成 git 仓里再跑一次**，看引擎会不会去读它被启动的那个仓库 (第一、二节就是这么测出来的)。**这一步只能在下面这个现建现扔的合成仓里跑；不得在任何真实仓库、尤其不得在私有仓或有未提交改动的工作树里跑。** 仓里只有刚写进去的那一个合成文件，并**留一个非空的暂存区**不提交 —— 泄漏正是从「未提交的暂存改动」那里观察到的：

   ```sh
   throwaway="$(mktemp -d)"
   cd "$throwaway"
   git init -q
   printf 'ACME 的季度报告写得不好，成本是 $1,000。\n' > foo.md
   git add foo.md   # 只 add 不 commit：造出一个非空暂存区
   # 这里跑第 2 步那条命令，输入仍是第 2 步那段合成文本
   ```

   判据：**引擎的输出里出现 `ACME` / `$1,000` / `foo.md` 这些只可能来自这个仓的合成字符串，就说明它读了工作目录** —— 记进本文，并确认预设走的是临时目录 + 白名单环境这条路径 (§一)。这样即使验出来了，外发的也只有我们自己造的假数据。

   跑完就删：

   ```sh
   cd / && rm -rf "$throwaway"
   ```

4. **把结果与 CLI 版本、型号名、日期写进本文**，通过才把型号写进 `src/limae/engines.py` 的预设表。
