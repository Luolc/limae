# ADR-0007：AI 腔规则家族的规范位置与第一批

- 日期：2026-08-31
- 承接：ADR-0005 §四 (确定性段 vs 语义段) 与 §六 (从语言习惯归纳出的规则先做 experimental)、ADR-0006 (可修复性 / 严重度 / 成熟度三轴与 `enable_experimental`)；配置层沿用 ADR-0003 与 ADR-0004

## 背景

ADR-0006 确定了 experimental 这条轴，但规则集里还没有 experimental 规则，`enable_experimental` 至今没有实际作用。ADR-0005 §六提出「从润色 pair 蒸馏 experimental 规则」，重点是中文 AI 腔与术语选词 —— 这也是 `docs/research/claudish-and-ai-slop-survey.md` §7.2 第 1 / 5 条建议的下一步实验：手工蒸馏一小批 experimental warning，再加一张带语境锚点的术语小表。

真正实施时，ADR-0005 / ADR-0006 都没有回答三件事：新规则的 id 如何命名、词表这类判定数据放在仓库的哪一层，以及逐行模型能覆盖 AI 腔的哪些部分。本 ADR 回答这三件事，并记录第一批规则的内容及其在真实语料上的误报率。

## 决定

### 一、规则 id 按家族分前缀，但前缀不是配置维度

规则 id 从此按家族 (family) 使用前缀，参考 ruff 的做法：

| 前缀 | 家族 | 第一批 |
| --- | --- | --- |
| `R` | 中文排版 (typography)：字符宽度、空格、标点 | R1–R11 (已有) |
| `A` | 中文 AI 腔 (AI tells)：套话、句式、黑话、聊天残留 | A1–A4 |
| `T` | 术语选词 (terminology)：`wrong = right` 的词表替换 | T1 |

- **前缀只是命名**：全部规则共用同一个 `disable` / `enable` / `severity` 命名空间，新增家族不需要新键。这与 ADR-0003 §二「键按规则 id 组织」和 ADR-0006 §五「规则不分语言」一致 —— `A` 不代表「中文规则包」，将来的英文 tells 会用另一批词表，而不是另一个开关。
- id 在家族内从 1 开始，保持稳定且不复用，与 `R` 一样。
- 术语选词单列 `T`，而不放进 `A`：它是唯一可修复的一支，判定数据的结构 (`wrong` / `right` / `anchors`) 也与 A 家族的短语表不同。

### 二、词表放 `spec/wordlists/`，是规范的一部分

A1 / A3 / A4 / T1 的判定依赖词表。词表放在仓库根目录的 `spec/wordlists/`，与 `spec/rules.md`、`spec/fixtures/` 平级：

- `A1.txt` / `A3.txt` / `A4.txt` —— UTF-8 纯文本，一行一条，忽略 `#` 注释和空行。
- `T1.toml` —— 一个 `entries` 数组，每条包含 `wrong` / `right` / `anchors`。

理由与 ADR-0001 将规范和黄金集放进 `spec/` 相同：**词表是判定的一部分，所以也是规范的一部分**。所有实现共用同一份词表，不放进任何单一实现的私有目录。**加一条词就是改规范，不需要改实现代码** —— 这正是 ADR-0005 §六 heuristic learning 需要的形式：规则和数据都是人能读懂、可回归、可删除的显式软件。

**当前不提供用户侧的词表增删接口**：词表固定在规范里，随包分发，既没有配置键，也不读取外部词表文件 —— 用户不能修改词表，只能用 `disable` 关闭整条规则，或用行内指令就地豁免。起步阶段不设计复杂形态；将来确实需要开放时 (项目专用词表、`extend_wordlist` 这类键)，另起 ADR，再讨论合并语义与校验。

Python 参考实现通过 `importlib.resources` 读取这些文件，`src/lo_md_lint/wordlists` 是指向 `spec/wordlists/` 的目录级软链 (与 `.claude/skills/` 指向 `.agents/skills/` 的方式相同)；editable 安装和打好的 wheel 都能解析这些文件，`uv run lo-md-lint` 与 `uvx --from . lo-md-lint` 两条路径都实测可以找到词表。

### 三、第一批只做逐行可判的规则，文档级密度留下一批

`spec/rules.md` 的「处理单位」和黄金集的 `.findings` 都采用逐行模型 (`<行号> <规则 id>`)。AI 腔中的**破折号密度、粗体密度、列表化行文**等判定属于文档级 —— 一处违规不对应某一行，无法写出报告位置。要做这些规则，得先为规范增加文档级 finding 的形式 (以及 `.findings` 的表达方式)，这是独立的一步。

**本批只收逐行可判的规则**，文档级密度规则留待下一批。这与调研 §6 的分层表一致：确定性 floor 里也分逐行与跨句两类。

### 四、第一批五条：全部 experimental + warning + 默认关

| id | 名 | 判定 (逐行) | 可修复性 | 默认严重度 | 成熟度 |
| --- | --- | --- | --- | --- | --- |
| A1 | 中文套话 | 行内出现 `A1.txt` 里的开场白 / 连接套话 | non-fixable | warning | experimental |
| A2 | 否定平行 | 同一行内「不是 … 而是 …」，相距 ≤ 20 字符 | non-fixable | warning | experimental |
| A3 | 互联网黑话 | 行内出现 `A3.txt` 里的黑话 | non-fixable | warning | experimental |
| A4 | 聊天残留 | 行内出现 `A4.txt` 里的整句级模板 | non-fixable | warning | experimental |
| T1 | 术语选词 | `T1.toml` 某条的 `wrong` 命中，且同行有该条锚点 | fixable | warning | experimental |

判定上的几项取舍都旨在压低误报：

- **A1 / A3 / A4 一行只报一处**：这类词往往成串出现，逐处报告只会刷屏。T1 每个命中各报一处，与修复一一对应。
- **A2 只收「不是 … 而是 …」，不收「不仅 … 更 …」**：递进句式在中文技术写作中是正常用法。20 字符的上限可以排除跨句的巧合。
- **A3 不收「对齐」「沉淀」「闭环」「生态」**：它们在技术文档中有正当用法 (对齐两份配置、闭环控制、依赖生态)，dogfood 也证实了这一点 (下节)。
- **T1 必须带锚点**：一个词是否该替换取决于语境 (调研 §5.3)，所以只有同一行出现该条自己的锚点 (`token` / `OAuth` / `cache` 这类) 时才报告和修改。锚点是语境证据，不是违规，因此在整行范围内查找，不受全局豁免约束 —— 最常见的锚点正是行内代码里的 `` `token` ``；违规本身仍受豁免约束。没有稳妥锚点或唯一替换词的直译词 (「门控」「一等公民」「契约」) 不进表。
- **不做 error 级单点禁词、不灌大词表、不做繁中本地化**，与调研 §7.3 一致。

**这五条规则及其词表条目都是可调项，不是本 ADR 定死的内容。** 具体收哪些规则、每张词表收哪些词，由实现方根据证据决定，用户不逐条审核；本 ADR 授权后续随时增删 —— 加词、删词、增加 A5、将某条降回去，都不需要新的 ADR。**校准与验收不阻塞合入**：experimental 的定位本来就是「边开发边校正」，误报要通过真实语料一轮轮打磨，而不是在合入前审完一张清单。真正需要另起 ADR 的是形式变化 (前缀约定、词表位置与格式、逐行 / 文档级模型、默认严重度这些)，不是清单内容。

五条规则全部为 experimental，唯一入口是 `enable_experimental = true` (ADR-0006 §三)；默认集不包含它们，现有消费方行为不变。默认严重度为 warning：单点 tell 的假阳性高 (调研 §2.4)，不适合由它们决定 CI 的退出码；用户需要更严时，可以用 `severity` 将单条规则改成 `error`。

### 五、dogfood 校准是这批的验收方式

experimental 的定义是「误报率还没在真实语料上验证过」(ADR-0006 §三)。这批的做法是：在四份真实中文 Markdown 语料上开启 `enable_experimental = true` 跑一遍，逐条人工判定命中是真阳性还是误报，将误报率高的词当场从词表删除，再把数字记入本 ADR。四份语料来自本仓和三个私有仓 (`machine-setup` / `wealth-management` / `butler`)，共 114 份 Markdown。

第一轮校准结果 (2026-08-31)：

| 语料 | 份数 | A1 | A2 | A3 | A4 | T1 | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `lo-md-lint` (本仓) | 18 | 2 | 12 | 7 | 3 | 4 | 28 处中有 27 处是规则文档在举例或转述调研原文 (`spec/rules.md`、`README.md`、本 ADR、`docs/research/`)，即 mention 而非 use；剩下 1 处是本 ADR 正文确实使用了该句式。规则每一处都判对了 |
| `machine-setup` | 40 | 0 | 1 | 0 | 0 | 0 | 真阳性 |
| `wealth-management` | 44 | 0 | 6 | 1 | 0 | 0 | 真阳性 |
| `butler` | 12 | 0 | 1 | 0 | 0 | 0 | 真阳性 |

三个私有仓共 96 份 Markdown、9 处命中，逐条人工判定后**全部是真阳性** —— 命中的确实是「不是 … 而是 …」这一句式本身，或词表中的黑话，没有一处是模式匹配意外命中。密度也不刺眼：平均每 10 份文档不到 1 处。

**校准中删掉的一条：`秘密` → `密钥`。这是本批的取舍，不是定论 —— 用户不认同删除理由，但不阻塞本批合入。** 删除前，它在四份语料中命中 56 处 (`machine-setup` 43、本仓 9、`wealth-management` 3、`butler` 1)。

- **用户立场**：如果一份文档中所说的 `secret` 就是 access secret / token，那么「零秘密」同样不对，应该写「零密钥」 —— 这些命中中有相当一部分不是误报，而是真的应该修改。
- **本批仍不收的理由**：`machine-setup` 与跨仓守则中的「秘密」大多**有意作为类别词 (category term) 使用** —— 密码、key、token、助记词统称秘密，守则原文就是「……等任何秘密」。T1 现有判据只有「同一行出现锚点」，无法区分「作为类别词的秘密」与「应译为密钥的 `secret`」；而 T1 是 fixable，判错就会真正改坏文本。宁可本批漏报，也不要在可自动修复的规则中误报。
- **第二批要收回这条，需要比同行锚点更细的判据**：例如将锚点限定为具体凭证名 (`OP_SERVICE_ACCOUNT_TOKEN`、`api_key` 这类)，而不是 `secret` / `key` 这类泛称，或者将「同一行」收紧为「同一句」。在有这样的判据前不收。

调研 §5.3 早已指出 `secret` 要按语境区分；这一轮 dogfood 将这点说得更具体：**同一行的英文锚点仍然不够细，不能作为所需的语境。** 删除的事实和理由记在 `T1.toml` 的注释中，backlog 由 orchestra 在合入后记入 `docs/tracker.md`。

**A1 与 A4 在三个私有仓中是零命中**：这说明两张词表没有误伤，但也说明它们的真阳性率尚未验证 —— 这正是它们保留在 experimental 的理由。

**这不是毕业判据。** 是否毕业为 stable，仍按 ADR-0006 §三由用户逐条裁决；本节只是把「是否验证过」从口头说法变成有数字的记录。

## 后果

- `spec/rules.md` 有三处变化：「通用模型」增加「词表」小节、「规则属性」增加前缀约定和实验规则清单、末尾增加 A1–A4 / T1 五条条目；「修复顺序」将 T1 排在最前 (选词替换出的字要进入后续所有规则的判定范围)。
- `spec/wordlists/` 是新增的规范数据层，`spec/README.md` 说明各实现如何读取它。
- `enable_experimental` 从今天起不再是空操作，`severity` 的默认值也不再「全是 error」。
- 现有消费方行为不变：不开 `enable_experimental` 就与 v0.6.0 完全一致，本仓自己的 dogfooding 钩子也不受影响。
- 下一批有两件事待办：**文档级密度规则**要先为规范增加文档级 finding 的形式；**英文 tells 词表**按 ADR-0006 §五属于同一套规则机制下的另一份词表，不是新的语言开关。两者由 orchestra 在合入后记入 `docs/tracker.md`。
- 本 ADR 不改 LLM 润色那条线 (ADR-0006 §四)：warning 不触发任何 model-based 修复。

accepted (2026-08-31)。
