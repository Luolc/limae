# limae 仓 PR 审查增量

用户级 `pr-review` 定轨道、优先级与 Verdict 格式，本文件只加严，不 supersede 它的任何条目。

**适用范围**：PR 改到 `spec/lexicon/zh.toml`、`spec/polish/zh.md`、`spec/wordlists/`、`site/index.html`、`tools/render_lexicon.py` 或 `rust/examples/render_lexicon.rs` 时，除通用文档轨外，逐条走下面的检查。碰不到这些路径的 PR，本文件不适用。

条目带 id (`L1`…)，供评论按 id 引用。id 只追加、不重排、不复用。

## 一、收词

- `L1` **收词要走 `zh.toml` 里 `threshold` 那几步**，PR 描述要写清它走到哪一步、卡在哪一句上、拿什么中文技术写作当证据。只写「读着别扭」不算走过 —— `threshold` 第一句就把「觉得别扭」排除在门槛之外。描述里没有这段，是 P1。
- `L2` **拿不准就是不收。** `threshold` 末句写明两种错的代价不对等：误收一个好词会让读者照词典把正常的中文改坏，漏收只是下次再补。所以审查方对一个证据不足的新词条给「先不收」，不给「再想想」。
- `L3` **收最小的那个词。** 病在哪个词上就收哪个词：审到多字词条先问，去掉后缀或修饰之后病还在不在 —— 还在就是收大了。同理，词条的字面变了 (拆细、改写)，`spec/polish/zh.md` 里提到同一个词的地方要一并看：两处**不要求同形**，`spec/polish/zh.md` 明写「判断的是这个搭配在这句话里成不成立，不是拿例子做词表匹配」；要看的是两处有没有互相矛盾 (一处收、另一处列为不必改)。矛盾是 P1，只是措辞不同不是缺陷。

## 二、词条正文的四栏

- `L4` **白 (`plain`)**：一句话的替代说法，短。**并列的几种说法之间用全角分号 `；`，不用顿号** (用户 2026-09-09 定案：「暂缓；先不动手」「记录；留痕；埋点」)。这是形式项，看到顿号直接报。并列几条不设上限 —— 上面第二个例子就是三条。
- `L5` **解 (`gloss`)**：只有「本意指 X，此处引申为 Y」两截 (或「某词逐字译来，此处指 Y」)。**一句判断都不留**，好坏一律归「病」。解里出现评价 (「没有道理」「生硬」「不该这么用」) 就是走错了栏，P1。
- `L6` **病 (`fault`) 里的判断是词条的论点本身，不是缺陷。** 「「按住」通常只表示物理上压住」正是这个词条要说的话，禁掉它等于禁掉词典。要报的是两件事 —— **断言的范围大过取证的范围**，或**断言写得不留余地**。四种形状：
  - 主语从「这个词在这个意思上」放大到这个词的全部用法、或放大到整个中文 (例如从「「装置」不用来说一份数据记录」滑成「「装置」只有一个意思」)；
  - 关于流行度、译法源流、历史的断言 (「一直没流行开」「是早年的一个生硬翻译」) 而 PR 描述里没有出处；
  - 把「我们没找到」写成「没有」，而 PR 描述里没写用什么方法找的 —— 这条按用户级 `W6` 处置；
  - 核心论点写成无条件的全称否定 (「中文没有这个引申」「从来不这么说」)，而不是留余地的写法 (「通常只表示……」「一般不作此引申」)。**判据不是句子里有没有「只」「没有」这些字** —— 用户 2026-09-09 定案的改写「「按住」通常只表示物理上压住，一般不作此引申」自己就带「只」；要看的是这个断言留不留得住例外。

  四种都是 P1，前三种要在 finding 里写出「取证覆盖到哪里、断言伸到哪里」这个差；报之前先看 PR 描述里 `L1` 那段证据，证据够就不是缺陷。
- `L7` **「病」里不写「中文里」「在中文里」「中文中」这类限定语。** 整部词典讲的就是中文，主语不必每句重申：写「「装置」通常只指实物设备」，不写「「装置」在中文里通常只指实物设备」。`fault` 里出现这类限定语一律提出来，按 P2 记 —— 它是形式项，不适用 `L16` 的「措辞按建议提」。**例外是那一句真的在拿中文与外语对照**，如「中文碰到 fixture 也没有定于一尊的译法」，主语确实需要，不报。只管 `fault` 一栏，`gloss` 与 `threshold` 正文不在内。
- `L8` **病的收尾要给替代说法**，没有替代说法的病是 P1：词典的读者要拿它改句子。替代说法本身要读着自然，但**判据是这句中文自不自然，不是形式上禁掉某个虚词** —— 用户 2026-09-09 把「按住」的收尾定成「停一下」「等一等」「先放着」，前两个去掉了「先」，第三个留着。所以「多余的『先』」与「几个替代重复同一个字头」都按 P2 建议提，不当形式项报。
- `L9` **四栏之外不要新增字段**，也不要在正文里塞只有生成器读得懂的标记 —— 两个生成器都要跟着改，见 `L13`。

## 三、例句

- `L10` **`before` 是引用，不得建议润色。** 它取自仓内或真实语料的原话；读着别扭正是它被收进来的原因。审查方对 `before` 的措辞不提意见。
- `L11` **例句的粒度要跟词条对上**：至少有一条 `before` 把词以词条的字面形态呈现出来。对不上时只提出来 (换例句还是改词条由用户定)，不代拟 `before`。
- `L12` **`after` 要像人说的话** —— 口语、语序贴着原句，不是把词机械替换掉。审到一条读着仍像机器写的 `after`，**直接给两三个候选**；只写「不自然」不算一条可处置的 finding，按 `O4` 降为 P2「需讨论」。

## 四、页面与两个生成器

- `L13` **样式与页面结构有两个生成器**：`tools/render_lexicon.py` (Python 参考实现) 与 `rust/examples/render_lexicon.rs` (Cargo example `render-lexicon`)，CSS 在两边各有一份，验收判据是同源产物逐字节一致。只改了一边是 P0 —— `tools/check_lexicon_render.sh` 会红，按 `B2` 处置。
- `L14` **`site/index.html` 是生成产物**，手改的痕迹一律不许进 PR。手改与「改了词典忘了重新生成页面」是同一个可观测后果 —— `tools/check_lexicon_render.sh` 红 (前者走 `site/index.html is out of date` 那条分支)，按用户级 `B2` **这就是 P0**，不另开一条 finding、也不降级成 P1。本文件的增量只在于**怎么说**：手改要指出它该回到哪个生成器里 (`L13`)，页面过期要指出重新生成那一步没跑。反过来，这道门绿着就说明提交的页面与生成结果逐字节相同，此时「看着像手改过」是看错了，不报。
- `L15` 词典条目自身、`site/index.html`、`spec/wordlists/` 的注释与 fixture 里出现词典收过的词，不算 dogfooding 违规，不报。

## 五、措辞归谁管

- `L16` **词典正文由用户口述，实现方不创作。** 审查方对「解」「病」「白」「例句」的措辞意见一律按 P2 建议提，不按缺陷提；只有本文件列出的形式要求 (`L1`–`L15`) 才是硬项。改一个词条的字面而 PR 描述里没写是用户哪一句话要求的，是 P1 —— 那是实现方在替用户创作。
