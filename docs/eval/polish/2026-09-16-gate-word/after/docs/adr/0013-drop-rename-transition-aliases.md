# ADR-0013：移除更名过渡期的全部旧名别名

- 日期：2026-09-03
- 承接：ADR-0008 §一 (更名对账表：仓名 / 包名 / 命令名 / hook id / 配置表与文件 / 指令前缀 / 忽略文件) —— 本 ADR 结束那张表里的过渡期；ADR-0003 §三 (两种同构配置载体) 的键结构不变，只是不再认旧拼法

## 背景

本工具原名 `lo-md-lint`，ADR-0008 决定改名为 `limae`，并采用「新旧并存、消费方自行迁移」的方式：命令名、pre-commit hook id、配置文件名与表名、行内指令前缀、忽略文件名六个方面都同时认新名和旧名，语义完全相同。这是过渡期应有的做法 —— 改名不该在消费方毫无准备时让它们的 CI 变红。

过渡期的前置条件今天已经解除。用户 2026-09-02 用 `gh repo list Luolc` 和全仓 `gh search code` 核对覆盖面：三个消费仓 (butler、wealth-management、machine-setup) 都已改用新的 `repo` / hook id / 命令名，**旧配置语法在全部仓零命中** —— 旧指令前缀、`[tool.lo-md-lint]` 表名、`lo-md-lint.toml`、`.lo-md-lint-ignore` 均未出现。因此，这次移除对已知消费方是 no-op，不需要跨仓协调。

保留旧名会增加成本，而且成本落在最不该有分支的地方：配置发现顺序中，为「同一层新旧同名并存」专门设了一条配置错误 (规范第 10 条)；忽略文件又为同一种并存设了相反的规则 (新名优先、不报错)。两条规则各自成立，放在一起却需要整段解释判据为何不矛盾。这段解释存在的原因就是旧名本身。规范里每多一条这样的内容，后续 Rust 实现就多一处必须复刻的行为。

用户 2026-09-03 裁定：一次性清掉六个方面的旧名。

## 决定

### 一、删掉的面

- **命令名**：`pyproject.toml` 的 `[project.scripts]` 只留 `limae`，删掉 `lo-md-lint` 入口。
- **pre-commit hook id**：`.pre-commit-hooks.yaml` 只留 `- id: limae`，删掉别名 hook。
- **配置文件名**：只认 `limae.toml`，不再认 `lo-md-lint.toml`。
- **配置表名**：只认 `[tool.limae]`，不再认 `[tool.lo-md-lint]`。
- **行内指令前缀**：只认 `limae-disable` / `limae-enable` / `limae-disable-next-line`，不再认 `lo-md-lint-` 一族。
- **忽略文件名**：只认 `.limae-ignore`，不再认 `.lo-md-lint-ignore`。

规范 (`spec/rules.md`) 中描述旧名的段落一并删除，包括「同一层新旧同名并存是配置错误」这条配置错误 (原第 10 条)，以及忽略文件中相反的「新名优先」。两条规则都只为新旧并存而设，旧名移除后便没有可能触发的输入。黄金 fixture `legacy-directive-prefix` 整组删除；`spec/fixtures/` 中描述新前缀行为的 `inline-disable-*` 三组保持不变，新前缀的覆盖不依赖被删的那组。

### 二、不补替代 fixture

被删的 `legacy-directive-prefix` 除了「识别旧前缀」之外，还有一个 case：`<!-- lo-md-lint-disabled -->` 这类拼错的名字按普通文本处理。这一点由规范中的通用规则覆盖 —— 「名字拼错的注释 (如 `limae-disabled`) 按普通文本处理」 —— 新前缀对应的 case 也已在既有 fixture 中。**不为「旧前缀不再生效」补负向 fixture 或负向测试**：旧前缀如今与其他拼错的名字没有区别，为它单独增加断言，等于长期在规则集中保留一个已经不存在的概念。

## 后果

- **0.13.0 起旧名一律失效。** 移除别名是 breaking change，版本从 0.12.0 跳到 0.13.0。消费方若仍有旧写法，hook id 与命令名会直接失败 —— pre-commit 找不到 hook id，shell 找不到命令。仓库地址不在此列：仓名改动在本次移除前已完成 (ADR-0008 §一)，旧 URL 由 GitHub 301 永久重定向，`repo:` 与 `uvx --from git+…` 使用旧地址仍可运行。
- **旧配置文件会被静默当成「没有配置」，不报错。** 这是这次移除中唯一没有提示的行为变化，也是最值得记录的一条：发现顺序只查找 `limae.toml` 与 `[tool.limae]`，留在原处的 `lo-md-lint.toml` 既不是配置来源，也不是配置错误 (规范里「没读到就不算错」)，因此这次运行会按默认全开执行。表现是「规则突然多了 / 关掉的规则又报了」，而不是出现一条错误信息。`.lo-md-lint-ignore` 同理：文件仍在，但不再排除任何内容，原本被忽略的文件会重新进入检查。**已知的三个消费仓都没有这类残留文件，因此这条今天没有受害者。它针对任何仍保留旧配置文件或旧忽略文件的 pre-0.13 消费方 —— 0.12 本身仍识别旧拼法，所以受影响的不只是从更早版本升级的仓库。**
- **规范少了一条配置错误。** 配置错误清单从 10 条回到 9 条。编号只是清单内的序号，不是稳定 id，实现不据此分流；删掉一条不会影响其余各条的含义。
- **ADR-0008 §一 那张对账表里的「待做」不再更新。** 按守则，ADR 被新 ADR 取代而不就地改写 —— 那张表记录的是写下时的状态，本 ADR 是其后续。

## 状态

accepted (2026-09-03)。
