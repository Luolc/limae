# ADR-0004：默认关闭的规则与 `enable` 键

- 日期：2026-08-31
- 承接：ADR-0003 (配置模型：`disable` 键、两种同构载体、CLI 优先)

## 背景

新一批空格规则 (R4–R9) 中，R9 (链接与 CJK 之间空格) 被裁决为**默认关闭、可打开**：上游规范将「链接两侧空格」列为争议项 (`docs/research/zh-typography-guidelines-survey.md` §3.10)，不适合默认强制，但要给希望启用它的仓库提供开关。ADR-0003 的模型「配置只能关，不能开」无法表达默认关闭的规则 —— 没有任何键能将它打开。

## 决定

### 一、规则条目可以标「默认关闭」

规范中每条规则默认启用，除非条目开头明确标为「默认关闭」(当前只有 R9)。「默认集」指所有默认启用的规则；「没有任何配置」始终等价于默认集，这条不变量从 ADR-0003 原样继承 —— R1–R8 的行为不因本 ADR 改变。

### 二、新增 `enable` 键，与 `disable` 对称

启用集 = (默认集 ∪ `enable`) − `disable`。`enable` 用于打开默认关闭的规则；列出默认启用的规则允许作为空操作，显式写出也无害。同一个 id 同时出现在两个键中是配置错误 —— 结果会随求值顺序而变，静默选择其中一种会让用户误解，必须显式二选一。

未采纳的替代方案：仿 ruff 的 `select` (全量重选启用集)。`enable` 只是向默认集中加回个别默认关闭的规则，语义小得多；真需要「只开某几条」时，再加 `select` 仍是向后兼容的扩展，与 ADR-0003 的 YAGNI 结论一致。

### 三、CLI 加 `--enable`，任一 flag 出现即整体覆盖配置文件

`--enable` 与 `--disable` 语法相同 (可重复、可逗号分隔)。命令行上只要出现两者之一，配置文件就整体不生效，缺席的另一个键按空算 —— 延续 ADR-0003「一次运行只有一个来源」的语义，临时试用的结果依旧不依赖仓库中的配置文件。

## 后果

- 配置模型的源文件仍是 `spec/rules.md`「配置」，本次同步改写；配置错误清单新增「`enable` 非字符串列表 / 含未知 id」与「同一 id 同时出现在两个键」。
- 黄金集的 `<case>.conf` 可以带 `enable` 键；runner 按 (默认集 ∪ `enable`) − `disable` 计算启用集。
- 不加配置的消费方升级仍是 no-op：默认集就是 R1–R8 全开 (加上后续默认启用的新规则)，R9 不开，不影响任何既有输出。
- 将来的默认关闭规则复用同一机制，不再改动配置模型。
