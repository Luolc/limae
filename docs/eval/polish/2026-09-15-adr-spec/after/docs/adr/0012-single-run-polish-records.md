# ADR-0012：单路润色也落会话态记录

- 日期：2026-09-01
- 修正：ADR-0008 §十 P0 中「不写盘」的说法；扩展 ADR-0009 §八 划定的会话态存储范围

## 背景

ADR-0008 §十 将 P0 描述为：

> **P0：hook 里的一次输出润色** —— 局部文本、不写盘、没有跨文件问题，正好用来 evolve prompt。

ADR-0009 因此只为 **A/B 台账**明确允许保存会话态 (§五、§八)，理由是它属于「运行时的调试 / 判据采集数据」。**未命中采样的轮次什么都不落。**

当时这样已经够用，因为 A/B 是采集判据的唯一方式。现在有两件事变了：

1. **A/B 被用户关掉了** (`LIMAE_HOOK_AB_RATE=0`)。现在只跑单路润色，但它不在磁盘上留下任何痕迹 —— 屏幕上出现过什么、模型拿到什么，事后只能从截图里找。2026-09-01 已因此在一次判断中引用错了一轮的字数。
2. **模型改写的方差很大**，不是近似固定的函数。同一段输入 (946 字、20 个 `**`) 连跑四次：

   | 样本 | 字数 | `**` | 逐字相同行 | linter |
   | --- | --- | --- | --- | --- |
   | 1 | 905 | 0/20 | 8/16 | 1 error (`zh-typography-1`) |
   | 2 | 947 | 20/20 | 14/16 | 干净 |
   | 3 | 946 | 20/20 | **16/16 (一字未改)** | 干净 |
   | 4 | 941 | 18/20 | 15/16 | 干净 |

   一次什么都没做，另一次删光格式并弄脏标点。

第二条决定了第一条的重要性：**改动 prompt 或规则后，只跑一次看结果证明不了任何事** —— 表中四次里只有一次粗体被吃掉，随便挑一次，都有 3/4 的概率看起来没问题。要判断一次改动是否有效，只能比较分布；而比较分布要求每一轮的输入和输出都留在磁盘上。**没有这份记录，`spec/polish/` 的任何改动都无法验收。**

## 决定

**每一次成功的单路润色都落一份记录**，位置 `<会话态目录>/polish/<message_id>.json`。

- **一条消息一份，重跑覆盖原来的记录。** 不追加，不加轮次后缀。生产记录要回答的是「在**真实且各不相同**的输入上，模型多久什么都不做一次、多久弄脏一次」，它会按消息自然累积；而「同一段输入跑 N 次」回答的是另一个问题 (固定输入的方差)，应由一次性测量脚本处理，不入库。给生产记录加轮次后缀，等于让人为重跑的样本混入真实分布。
- **只在润色成功时写。** 消息太短而未润色、引擎未应答、修复阶段崩掉，都不写 —— 记录的是「polish 做了什么」，不是事件日志。失败已有 `diagnostics.jsonl` (ADR-0009 §六 的落地)。
- **三份文本**：`original` (助手写的原文)、`text` (模型改完、**未过**本仓规则)、`displayed` (用户实际看到的，即 `text` 再过一遍确定性修复)。分开记录，才能回答「这一轮的整洁有多少来自模型、有多少是规则修出来的」 —— 合成一份就永远无法回答；而**计算模型的弄脏率必须用 `text`**，用 `displayed` 会低估它。口径与 ADR-0009 为 A/B 台账定义的 `text` / `displayed` 一致。
- **边界与 A/B 台账逐条相同**：会话态目录、`0600` / `0700`、不进任何仓库、不经 agent 间通道传递、随会话目录一起在同一个 prune 中过期 (ADR-0009 §五、§八)。写失败时 fail-open：记一行诊断，改写照常上屏。

**「不写盘」的含义在此明确**：它是指**不动用户的文件、不产生需要人审的旁路产物**，这也是 ADR-0008 §七「不做旁路目录」要避免的事；它**不**是指「不许有会话态临时状态」。ADR-0009 已在 A/B 台账上按这个理解开过一次口子，本 ADR 只是明确写下这条理解，并将范围从「采样命中的那 1/10」扩到「每一次成功润色」。

## 后果

- **磁盘上留存的助手回复变多了**：此前只有命中采样的轮次 (起步约 1/10)，现在是每一次成功润色的轮次。这是本 ADR 的真实代价，应写在这里，不能藏在实现里。三条边界不变 —— 只在会话态目录、只有本用户可读、24 小时后随会话清掉 —— 红线也不变：**不进本仓库、不经 agent 间通道传递**。
- **`spec/polish/` 的改动从此可以验收。** 「行内强调进保护清单」与「结构不变量校验」(ADR-0008 §八 已决定、§十 排在 P1) 都要通过比较改动前后的分布判断是否有效，本 ADR 是它们的前提。
- **P0 与 P1 的区别不再是「写不写盘」**，而是「动不动用户的文件」。P1 的 `limae polish <file>` 原地改文件，走 `git diff` 人审；P0 只写自己的会话态目录。
- 采样率、保留期、记录字段仍可调整，不需要新 ADR；只有形制变化才需要新 ADR —— 记录落在仓库里、跨 agent 传递，或者保留期超出会话，三者任意一项都要重新决定。

## 状态

accepted (2026-09-01)。
